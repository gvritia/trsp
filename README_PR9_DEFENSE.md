## Вопрос 15. `annotate()` и `F()`: изменить выражение и объяснить результат

1. В `delivery_orders/views.py` найдите функцию `order_list`. Покажите импорт `F` и часть запроса:

   ```python
   .annotate(
       client_name=F("client__name"),
       courier_name=F("courier__name"),
   )
   ```

2. Объясните: `client` и `courier` — внешние ключи модели `Order`. Запись `client__name` означает поле `name` связанного клиента. `F()` задаёт ссылку на поле для SQL-запроса, а `annotate()` добавляет к каждому объекту заказа временные атрибуты `client_name` и `courier_name`. Значение берётся из связанных таблиц при выполнении запроса. Новое поле в базе и миграция не создаются. Для заказа без курьера `courier_name` равно `None`.
3. Ниже в этой же функции покажите словарь `rows`: он получает `order.client_name` и `order.courier_name`. Затем откройте `order_row.html` и покажите `{{ order.client_name }}` и `{{ order.courier_name|default:"Не назначен" }}`. Откройте `/orders/` в браузере: в таблице видны имена клиентов и курьеров.
4. **Измените выражение на защите:** временно замените только `client_name=F("client__name")` на `client_name=F("client__phone")`, сохраните файл и обновите `/orders/`. В столбце клиента вместо имени появится телефон из связанной записи. Атрибут `client_name` в контексте и шаблоне остался тем же; поменялся источник значения в запросе.
5. Верните `client_name=F("client__name")`, сохраните файл и обновите страницу. Проверьте, что снова отображается имя.

**Короткий ответ преподавателю:** «`F("client__name")` ссылается на поле связанной таблицы клиентов. `annotate()` добавляет значение к каждому заказу как временный атрибут; view передаёт его в шаблон. После замены на `F("client__phone")` в том же месте страницы показывается телефон, потому что ORM выбирает другое поле связанного клиента».

## Вопрос 16. Получить объект и обработать отсутствие

1. В `delivery_bookings/urls.py` покажите маршрут `<int:booking_id>/`: число из адреса передаётся аргументом `booking_id` в `booking_detail`.
2. В `delivery_bookings/views.py` найдите функцию `booking_detail` и покажите:

   ```python
   booking = get_object_or_404(_booking_queryset(), pk=booking_id)
   ```

   Объясните: `_booking_queryset()` заранее подгружает заказ, клиента и курьера через `select_related()`. `pk=booking_id` ищет запись с указанным первичным ключом. Если запись есть, функция получает объект и передаёт его в `booking_detail.html`; если записи нет, `get_object_or_404()` вызывает `Http404`, и Django возвращает ответ со статусом 404.
3. В `booking_detail.html` покажите вывод `booking.id`, даты, заказа, клиента и курьера. В браузере откройте существующую запись из `/bookings/`: адрес будет вида `http://127.0.0.1:8000/bookings/1/`, где вместо `1` используйте **фактический ID** вашей записи. Покажите страницу с данными.
4. В адресной строке замените ID на заведомо отсутствующий, например `999999`: `http://127.0.0.1:8000/bookings/999999/`. Покажите страницу 404. Если такой ID вдруг есть, выберите большее число. При обычном локальном запуске с `DEBUG=1` Django может показать техническую страницу 404; это по-прежнему корректный HTTP-ответ 404, а не необработанное исключение или ошибка 500.

**Короткий ответ преподавателю:** «Для существующего ID `get_object_or_404()` возвращает `Booking`, и представление показывает его данные. Для отсутствующего ID он вызывает `Http404`; Django формирует ответ 404. Изменение числа в URL меняет первичный ключ, по которому выполняется поиск».
