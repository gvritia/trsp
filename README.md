# Система планирования маршрутов доставки

## Назначение

Учебная система для учёта клиентов, курьеров, заказов и маршрутов доставки.
Существующее консольное приложение дополнено веб-интерфейсом Django для
просмотра данных. Консольная и веб-версии используют одни и те же классы и
JSON-файлы.

## Возможности

Консольная версия позволяет вести клиентов, создавать и искать заказы,
назначать курьеров с учётом грузоподъёмности, отменять заказы, составлять и
завершать маршруты. Она поддерживает фильтрацию, сортировку, расчёт процента
назначенных заказов и сохранение изменений в JSON.

Веб-интерфейс ПР5 работает только в режиме просмотра: показывает общую
статистику, списки заказов и маршрутов, а также страницы отдельных объектов
с их существующими связями. Добавление и изменение данных в браузере не
реализовано.

## Используемые технологии

- Python 3.10+;
- Django 5.2;
- HTML и Bootstrap 5.3 через CDN;
- JSON для предметных данных;
- pytest для тестов;
- flake8 для проверки стиля;
- Black для форматирования.

## Предметная область

Клиент оформляет заказ с адресом и весом. Курьер может быть назначен на
заказ, если он активен и его текущая загрузка позволяет принять груз.
Маршрут объединяет несколько заказов одного курьера. После завершения
маршрута связанные заказы получают статус «доставлен».

## Основные сущности

- `Person` — абстрактный базовый класс с идентификатором и именем.
- `Client` — клиент с номером телефона, наследник `Person`.
- `Courier` — курьер с грузоподъёмностью и признаком активности, наследник
  `Person`.
- `Order` — заказ с адресом, весом, статусом и ссылками на клиента и,
  при назначении, курьера.
- `Route` — маршрут с курьером, списком заказов и статусом.

## Страницы веб-интерфейса

| URL | Назначение | View-функция |
| --- | --- | --- |
| `/` | Главная и показатели | `homepage.views.index` |
| `/orders/` | Список заказов | `delivery_orders.views.order_list` |
| `/orders/<int:order_id>/` | Детали заказа | `delivery_orders.views.order_detail` |
| `/routes/` | Список маршрутов | `delivery_routes.views.route_list` |
| `/routes/<int:route_id>/` | Детали маршрута | `delivery_routes.views.route_detail` |
| Любой другой URL | Страница 404 | `homepage.views.page_not_found` |

Для несуществующего ID заказа или маршрута возвращается HTTP 404 со ссылкой
назад к списку. Общая страница 404 для неизвестного URL отображается при
`DEBUG=False`.

## Основные операции

Через веб-интерфейс доступны просмотр статистики, списков и деталей заказов
и маршрутов. Для отображения используются существующие функции загрузки
объектов, поиска по ID, сортировки и расчёта эффективности.

Создание клиентов, заказов и маршрутов, назначение курьера, отмена заказа и
завершение маршрута остаются в консольной версии. Веб-формы и изменение
объектов через браузер отложены до следующих работ.

## Хранение данных

Предметные данные находятся в `data/clients.json`, `data/couriers.json`,
`data/orders.json` и `data/routes.json`. Связи записаны идентификаторами, а
`storage.py` при загрузке восстанавливает объектные ссылки. Веб-страницы
читают эти файлы через `load_delivery_data()` и не изменяют их. Django ORM
для предметных сущностей не используется. `db.sqlite3` создаётся только
стандартными служебными миграциями Django и исключён из Git.

## Структура проекта

```text
trsp/
├── manage.py                 # Управление Django
├── delivery_planner/         # Настройки, корневые URL, ASGI/WSGI
├── homepage/                 # Главная, общий HTML-каркас, глобальная 404
├── delivery_orders/          # Список и детали заказов
├── delivery_routes/          # Список и детали маршрутов
├── main.py                   # Консольное меню
├── models/                   # Существующая объектная модель
├── storage.py                # Загрузка/сохранение JSON и связей
├── utils.py                  # Безопасный ввод чисел для консоли
├── data/                     # JSON-файлы предметной области
├── tests/                    # Тесты старой логики и веб-страниц
├── docs/pycharm_setup.md     # Форматирование в PyCharm
├── requirements.txt
├── setup.cfg                 # Конфигурация flake8
└── pyproject.toml            # Конфигурация Black
```

## Назначение основных модулей

`delivery_planner` задаёт настройки Django и подключает URL приложений.
`homepage` формирует общий HTML-документ функцией `page(title, content)`,
главную страницу и обработчик 404. `delivery_orders` и `delivery_routes`
предоставляют только read-only view-функции для соответствующих сущностей.
Пакет `models` хранит прежние классы и предметные операции; в `models.py`
новых Django-приложений предметных ORM-моделей нет. `storage.py` читает и
сохраняет JSON. `tests` проверяет объектную модель, хранилище и веб-страницы.

## Запуск

Команды выполняются из корня репозитория в активированном виртуальном
окружении:

```bash
python -m pip install -r requirements.txt
python manage.py migrate
python manage.py check
python manage.py runserver
```

Откройте [http://127.0.0.1:8000/](http://127.0.0.1:8000/).
Bootstrap загружается через CDN, поэтому для оформления нужен интернет.

Старая консольная версия запускается отдельно:

```bash
python main.py
```

## Тестирование

```bash
python -m pytest -v
```

## Проверка качества

```bash
python -m flake8 . --extend-exclude=venv
```

В PyCharm встроенное форматирование запускается через **Code → Reformat
Code** (`Ctrl+Alt+L`); подробнее в `docs/pycharm_setup.md`.

## Текущее состояние

ПР5 добавляет базовый Django-проект в существующий репозиторий, главную
страницу, два раздела со списками и деталями реальных JSON-объектов,
единую навигацию и обработку 404. Консольное приложение и старые тесты
сохранены.

## План дальнейшего развития

В следующих практических работах возможны Django ORM, перенос предметных
данных в базу, шаблоны, формы и CRUD. В ПР5 они намеренно не реализованы.
