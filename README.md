# Система планирования маршрутов доставки

Учебный проект для учёта клиентов, курьеров, заказов, маршрутов и бронирования курьеров на дату. Веб-интерфейс использует Django ORM; консольный интерфейс в `main.py` продолжает работать с исходными JSON-файлами.

## Модели и связи

| Модель | Поля и назначение | Связи |
| --- | --- | --- |
| `homepage.Client` | имя, телефон | один клиент — много заказов (`client.orders`) |
| `homepage.Courier` | имя, грузоподъёмность, активность | один курьер — много назначенных заказов и бронирований |
| `delivery_orders.Order` | адрес, вес, статус | обязательный `client`, необязательный `courier` |
| `delivery_routes.Route` | статус маршрута | много заказов через `RouteOrder`; заказ не может входить в два маршрута |
| `delivery_bookings.Booking` | дата, признак отмены | обязательные `order` и `courier`; отменённая запись остаётся в истории |

Для действующих бронирований действуют частичные уникальные ограничения: один курьер на дату и одна бронь на заказ. Поиск свободных курьеров исключает только неотменённые бронирования, проверяет активность курьера и грузоподъёмность. Маршрут получает курьера из связанных заказов; `RouteOrder.clean()` не разрешает включить заказ без курьера или смешать курьеров в одном маршруте.

## Данные и миграция с предыдущей работы

Текущая база Django — `db.sqlite3` (файл не хранится в Git). Прежняя предметная база `data/delivery.sqlite` остаётся на месте как источник переноса и для демонстрации практической работы с прямым SQL. Команда `import_legacy_data` читает из неё клиентов, курьеров, заказы, связи маршрутов и **все бронирования, включая отменённые**. Если файла нет, она загружает четыре исходных `data/*.json`; в этом случае бронирований в источнике нет. Данные копируются в одной транзакции. Команда отказывается перезаписывать уже заполненные ORM-таблицы.

```powershell
python -m pip install -r requirements.txt
python manage.py migrate
python manage.py import_legacy_data
python manage.py check
python manage.py runserver
```

Для переноса из другого файла: `python manage.py import_legacy_data --source путь/к/старой.sqlite`. Если ORM-таблицы уже заполнены, команду повторять не требуется. Исходные JSON, прежняя SQLite и консольные сценарии не меняются при работе сайта. При новом развёртывании из Git, где SQLite отсутствует, импорт берёт исходные JSON.

## Страницы

| URL | Сценарий |
| --- | --- |
| `/` | фактические количества клиентов, курьеров, заказов и маршрутов |
| `/orders/` | поиск по адресу, клиенту и курьеру, фильтр по статусу, пагинация |
| `/orders/<id>/` | детали заказа, клиент, курьер, действующая бронь |
| `/routes/`, `/routes/<id>/` | маршруты и связанные заказы |
| `/bookings/available/` | поиск свободных курьеров на дату и по весу заказа |
| `/bookings/` | действующие и отменённые брони, отмена действующей брони |
| `/statistics/` | показатели, группировка заказов, нагрузка курьеров и бронирования |

Представления в `homepage/`, `delivery_orders/`, `delivery_routes/` и `delivery_bookings/` обращаются к моделям Django. Они передают данные в существующие шаблоны через контекст. Для отсутствующих заказов, маршрутов и URL возвращается HTTP 404. Формы создания и отмены брони требуют POST и CSRF-токен.

## Проверки

```powershell
python manage.py makemigrations --check --dry-run
python manage.py showmigrations
python manage.py check
python -m pytest -q
python -m flake8 .
```

Тесты `tests/test_orm.py` проверяют связанные объекты, запрет смешанных маршрутов, создание и отмену брони, освобождение курьера и ограничение уникальности. Веб-тесты проверяют страницы, поиск, фильтр, пагинацию, статистику, 404 и пользовательский путь бронирования. [Указатель ПР9](docs/pr9_orm_checklist.md) содержит команды проверки и 15 ORM-выражений для демонстрации. Исходные SQL-сценарии и их тесты сохранены как материал предыдущей практической работы; они больше не обслуживают Django-страницы. Для их демонстрации см. [чек-лист ПР7](docs/pr7_checklist.md) и [вопросы оценивания](docs/pr7_grading_7_6.md).

Сайт открывается по адресу [http://127.0.0.1:8000/](http://127.0.0.1:8000/). Настройка PyCharm описана в [docs/pycharm_setup.md](docs/pycharm_setup.md).
