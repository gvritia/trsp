# Система планирования маршрутов доставки

Консольное объектно-ориентированное приложение для создания заказов,
распределения нагрузки между курьерами и управления маршрутами доставки.

## Возможности

- просмотр, создание, поиск и сортировка заказов;
- просмотр курьеров и расчёт их текущей загрузки;
- проверка доступности курьера с учётом грузоподъёмности;
- назначение курьера и отмена заказа;
- ведение списка клиентов и поиск по имени или телефону;
- создание маршрутов из назначенных курьеру заказов;
- завершение маршрута с переводом заказов в статус «доставлен»;
- расчёт процента назначенных заказов;
- загрузка и сохранение объектной модели в JSON;
- обработка некорректного ввода и ошибок файлов.

## Объектная модель

### `Person`

Абстрактный базовый класс для участников системы. Хранит идентификатор и имя,
задаёт общий интерфейс строкового представления и сериализации.

### `Client`

Наследуется от `Person`. Хранит номер телефона, проверяемый через свойство
`phone`. Метод `from_data()` создаёт объект из JSON-данных, `to_data()`
подготавливает данные для сохранения.

### `Courier`

Наследуется от `Person`. Хранит грузоподъёмность и состояние активности.
Методы `current_load()` и `is_available()` рассчитывают загрузку и возможность
принять новый заказ.

### `Order`

Хранит ссылки на объект `Client` и, после назначения, на объект `Courier`.
Методы `assign_courier()`, `cancel()` и `mark_delivered()` изменяют состояние
конкретного заказа. `validate_weight()` реализован как статический метод.

### `Route`

Хранит ссылку на объект `Courier` и коллекцию объектов `Order`. Метод
`complete()` завершает маршрут и переводит связанные заказы в состояние
«доставлен».

## Принципы ООП

- **инкапсуляция** — проверяемые значения хранятся в закрытых атрибутах
  `_phone` и `_capacity` и изменяются через свойства;
- **наследование** — `Client` и `Courier` наследуются от `Person`;
- **полиморфизм** — объекты разных классов выводятся общей функцией через
  собственные реализации `__str__()`;
- **композиция** — `Order` содержит объекты клиента и курьера, а `Route`
  содержит курьера и заказы.

Коллекции приложения содержат объекты классов, а не словари. Функции поиска,
сортировки и фильтрации оставлены обычными функциями, поскольку работают с
коллекциями объектов.

## Хранение данных

Файлы в каталоге `data/` содержат только JSON-совместимые значения. Связи
между сущностями сохраняются идентификаторами `client_id`, `courier_id` и
`order_ids`. При загрузке модуль `storage.py` восстанавливает ссылки между
объектами; при сохранении объекты преобразуются обратно в словари.

## Структура проекта

- `main.py` — точка запуска и консольное меню;
- `models/people.py` — абстрактный класс `Person`;
- `models/clients.py` — класс `Client` и функции работы с клиентами;
- `models/couriers.py` — класс `Courier` и функции работы с курьерами;
- `models/orders.py` — класс `Order` и функции работы с заказами;
- `models/routes.py` — класс `Route` и функции работы с маршрутами;
- `storage.py` — преобразование JSON в объекты и объектов в JSON;
- `utils.py` — безопасный ввод чисел;
- `data/` — JSON-файлы клиентов, курьеров, заказов и маршрутов;
- `tests/` — автоматизированные тесты классов, функций и связей;
- `docs/pycharm_setup.md` — форматирование и проверка кода в PyCharm;
- `.editorconfig` и `pyproject.toml` — параметры форматирования.

## Требования

- Python 3.10 или новее;
- Black 24.0 или новее;
- flake8 7.0 или новее;
- pytest 8.0 или новее.

Установка зависимостей:

```bash
python -m pip install -r requirements.txt
```

Дополнительные библиотеки для объектной модели не нужны: она реализована
средствами стандартной библиотеки Python.

## Запуск программы

Команды выполняются из корня проекта:

```bash
python main.py
```

## Форматирование и проверка

```bash
python -m black .
python -m flake8
python -m pytest -v
```

В PyCharm встроенное форматирование запускается командой **Code → Reformat
Code** (`Ctrl+Alt+L`). Подробная настройка описана в
[`docs/pycharm_setup.md`](docs/pycharm_setup.md).
