# Система планирования маршрутов доставки

## Назначение проекта

Учебная система для учёта клиентов, курьеров, заказов и маршрутов доставки.
Консольное приложение дополнено Django-интерфейсом для просмотра данных.
Обе версии используют одни и те же классы предметной области и JSON-файлы.

## Используемые технологии

- Python 3.10+, Django 5.2 и Django Template Language;
- HTML, собственный CSS и JavaScript, Bootstrap 5.3 через CDN;
- JSON для предметных данных;
- pytest для тестов, flake8 для проверки стиля, Black для форматирования;
- Git для контроля версий.

Зависимости перечислены в `requirements.txt`. Для оформления страниц через
Bootstrap CDN требуется подключение к интернету; собственные CSS, JavaScript
и изображение обслуживаются Django staticfiles.

## Предметная область

`Person` — общий абстрактный класс с ID и именем. От него наследуются
`Client` с телефоном и `Courier` с грузоподъёмностью и активностью. `Order`
содержит адрес, вес, статус, клиента и при назначении курьера. `Route`
объединяет заказы одного курьера и имеет статус. Консольная версия позволяет
создавать и искать заказы, назначать курьеров, отменять заказы, составлять
и завершать маршруты. Веб-версия пока работает только на чтение.

## Веб-интерфейс

| URL | Страница | View-функция |
| --- | --- | --- |
| `/` | Главная и показатели | `homepage.views.index` |
| `/orders/` | Список заказов | `delivery_orders.views.order_list` |
| `/orders/<int:order_id>/` | Детали заказа | `delivery_orders.views.order_detail` |
| `/routes/` | Список маршрутов | `delivery_routes.views.route_list` |
| `/routes/<int:route_id>/` | Детали маршрута | `delivery_routes.views.route_detail` |
| Неизвестный URL | Страница 404 | `homepage.views.page_not_found` |

Отсутствующие заказы и маршруты также возвращают HTTP 404 с переходом к
соответствующему списку. Общий обработчик неизвестных URL проверяется при
`DEBUG=False`.

## Django Templates

Общий каркас находится в `templates/base.html`: он содержит HTML-документ,
Bootstrap, подключение собственной статики, footer и блоки `title` и
`content`. Все страницы используют `{% extends "base.html" %}` и переопределяют
эти блоки. Навигация вынесена в `templates/includes/navigation.html` и
подключается через `{% include %}`. Фрагменты строк заказов, статуса заказа
и карточек маршрутов находятся в `templates` соответствующих приложений.

View-функции загружают существующие объекты, передают необходимые данные в
`context` и вызывают `render()`. Перебор заказов, маршрутов и заказов
маршрута выполняется в шаблонах через `{% for %}`; пустые списки обрабатываются
через `{% empty %}`. Условия `{% if %}` показывают назначенного курьера и
оформляют реальные статусы. Бизнес-логика остаётся в Python-модулях.

## Именованные URL

Каждое приложение определяет `app_name` и маршруты с `name`. Используются
пространства имён `homepage`, `delivery_orders` и `delivery_routes`.
Внутренние ссылки в шаблонах строятся через `{% url %}`, поэтому адреса не
зашиты в разметку.

## Фильтры шаблонов

- `length` — количество заказов, маршрутов и заказов в маршруте;
- `floatformat:1` — отображение веса и процента назначенных заказов;
- `truncatechars:48` — компактный адрес заказа в строке таблицы;
- `default` — текст «Не назначен», когда у заказа нет курьера.

## Статические файлы

В `base.html` и навигации используется `{% load static %}`. Файлы приложения
`homepage`:

- `static/homepage/css/style.css` — цветовая схема, карточки, статусы,
  навигация и кнопка возврата наверх;
- `static/homepage/js/main.js` — показ кнопки после прокрутки и плавный
  переход к началу страницы;
- `static/homepage/img/delivery-logo.svg` — логотип доставки с атрибутом
  `alt` в навигации.

## Хранение данных

Клиенты, курьеры, заказы и маршруты по-прежнему хранятся в `data/*.json`.
`storage.py` восстанавливает объектные связи, а представления Django только
читают эти объекты. Django ORM для предметных сущностей пока **не используется**;
`db.sqlite3` нужен только стандартным служебным миграциям Django. Django
Forms и изменение данных через браузер также **не реализованы**.

## Запуск

Из корня репозитория в активированном виртуальном окружении:

```bash
python -m pip install -r requirements.txt
python manage.py migrate
python manage.py check
python manage.py runserver
```

Откройте [http://127.0.0.1:8000/](http://127.0.0.1:8000/).
Консольная версия запускается командой `python main.py`.

## Тесты

```bash
python -m pytest -v
```

## Проверка качества

```bash
python -m flake8 . --extend-exclude=venv
```

В PyCharm форматирование доступно через **Code → Reformat Code**
(`Ctrl+Alt+L`); дополнительная информация — в `docs/pycharm_setup.md`.
